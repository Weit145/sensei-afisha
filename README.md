## Запуск через Docker

Создайте `.env` из примера и задайте в нём `JWT_SECRET_KEY` (например, с помощью `openssl rand -hex 32`):

```sh
cp .env.example .env
```

Впишите сгенерированное значение после `JWT_SECRET_KEY=`. Пароль `ADMIN_PASSWORD`
для начального аккаунта `admin` можно задать самостоятельно (8–128 символов)
или оставить пустым для автоматической генерации. Затем запустите:

```sh
make up
```

Фронтенд доступен на `http://localhost:5173`, API и Swagger — на
`http://localhost:8080` и `http://localhost:8080/docs`. Фронтенд проксирует
`/api` и `/uploads` в контейнер приложения. При запуске Compose дожидается
готовности PostgreSQL, применяет миграции Alembic, создаёт начальный аккаунт
`admin`, если его ещё нет, и запускает API. Данные PostgreSQL и загруженные
изображения хранятся в Docker volumes.

Настройки портов и базы можно задать в `.env` по образцу `.env.example`.
Порт фронтенда задаётся `FRONTEND_PORT` (по умолчанию `5173`). `DATABASE_URL`
из примера предназначен для запуска приложения на хосте; внутри Compose адрес
базы собирается из `POSTGRES_*` и имени сервиса `db`.

Чтобы добавить три демонстрационных концерта с постерами в локальную базу,
после `make up` выполните:

```sh
make seed-examples
```

Скрипт попросит пароль `admin` без отображения ввода. Для запуска без терминала
передайте его через переменную окружения `SEED_ADMIN_PASSWORD`; если пароль был
сгенерирован автоматически, он указан в `docker compose logs migrate`.

Команда создаёт демонстрационную площадку и концерты через API. Повторный
запуск не дублирует записи с теми же названиями. Исходные постеры лежат в
`frontend/public/posters`, загруженные копии — в Docker-томе `uploads_data`.

```sh
make logs                           # логи сервисов
make migrate                        # применить миграции вручную
make revision MESSAGE="add events"  # создать ревизию по изменениям моделей
make down                           # остановить сервисы, сохранив данные
make delete                         # остановить сервисы и удалить данные БД
```

Первая ревизия создаёт таблицу `users`. Для локального запуска Alembic нужен доступный PostgreSQL и подходящий `DATABASE_URL`, затем можно выполнить `alembic upgrade head`.

## Начальный администратор

Скрипт `src/scripts/create_admin.py` запускается сервисом `migrate` после успешных миграций, в том числе при `make migrate`. Создаётся аккаунт с username `admin`, ролью `admin` и хешем пароля. Если `ADMIN_PASSWORD` не задан или пустой, генерируется случайный пароль; он выводится в логах `migrate` только при создании аккаунта. Сохраните его сразу:

```sh
docker compose logs migrate
```

Пароль в открытом виде не сохраняется в БД, но остаётся доступен в логах контейнера до их удаления. Для развёртывания вне локальной разработки задайте собственный секрет через `ADMIN_PASSWORD` и ограничьте доступ к логам.

Повторный и одновременный запуск не создают дубликаты: используется уникальность username и `ON CONFLICT DO NOTHING`. Существующий аккаунт, его пароль и сессии не меняются. Изменение `ADMIN_PASSWORD` в `.env` само по себе не сбрасывает пароль уже созданного админа. Если username `admin` занят обычным пользователем, скрипт завершится с ошибкой, не повышая его права. Другие администраторы не удаляются: гарантируется единственный начальный аккаунт с username `admin`, а не единственная запись с ролью `admin` во всей БД.

Без `ADMIN_PASSWORD` или с пустым значением пароль генерируется автоматически. Явно заданный некорректный пароль (например, короче 8 символов) по-прежнему вызывает ошибку. Если аккаунт уже существует с ролью admin, его пароль не меняется. `.env` не коммитьте; для паролей со спецсимволами используйте одинарные кавычки вокруг значения.

При запуске без Docker выполните из корня проекта:

```sh
poetry run alembic upgrade head
poetry run python -m src.scripts.create_admin
```

Сам по себе `alembic upgrade head` создаёт схему, но не запускает этот скрипт. Для входа используйте обычную ручку `/api/auth/login` с username `admin` и заданным паролем, включая CSRF-заголовок из [инструкции авторизации](docs/auth.md#csrf-заголовок-и-swagger).

Проверка в отдельных временных PostgreSQL-базах: `RUN_AUTH_DB_TESTS=1 poetry run python -m unittest discover -s tests -p test_create_admin.py -v`. Пользователь БД должен иметь право CREATE DATABASE; основная база не изменяется.
