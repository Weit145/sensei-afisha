# Обновления интерфейса

WebSocket: `/api/ws`. Подключение доступно гостям.

Для глобальных обновлений отправьте `{"action":"leave_to_main_menu"}` и дождитесь `{"type":"unsubscribed"}`. Новая афиша приходит с `n_type: 1`; после события перечитайте `GET /api/afisha` и покажите уведомление.

Для обсуждения и отзывов отправьте `{"action":"switch_afisha","afisha_id":"UUID"}`. После подтверждения подписки обновите историю и отзывы, чтобы восстановить события, пропущенные при переподключении.

Типы уведомлений:

| Событие | Признак | Действие клиента |
| --- | --- | --- |
| Новая афиша | `n_type: 1` | Уведомить и обновить список афиш |
| Новое сообщение | `n_type: 2` | Перечитать сообщения концерта |
| Создание, изменение или удаление отзыва | `n_type: 3` | Перечитать отзывы и обновить рейтинг/количество |
| Изменение числа заинтересованных | `type: "followers_updated"` | Обновить счётчик указанной афиши |

Уведомления 1–3 содержат `text`, `user_id`, `nickname`. Данные уведомления не заменяют сохранённые сообщения или отзывы; перечитывайте их через GET.

`GET /api/afisha/{afisha_id}/reviews` возвращает `nickname` в каждом элементе `items`. Это имя автора из таблицы пользователей, поэтому оно доступно уже при первой загрузке списка. То же поле присутствует в ответах POST и PATCH отзыва. Если аккаунт автора удалён, `author_id` и `nickname` равны `null`; сам отзыв остаётся в списке, а интерфейс показывает «Удалённый участник».

Счётчик рассылается всем локальным соединениям, в том числе на главной странице:

```json
{
  "type": "followers_updated",
  "afisha_id": "4e036140-87f8-4e0b-b6e7-f3349c4898fc",
  "followers_count": 2
}
```

«Хочу пойти» сохраняется через `POST /api/afisha/{afisha_id}/follow`, удаляется через `DELETE` того же пути. Нужен Bearer-токен. Оба запроса возвращают `204` и допускают повторение без дубликатов. После входа список отмеченных UUID загружается через `GET /api/auth/me/follows`; список принадлежит текущему пользователю и не кешируется.

Во время сохранения повторный клик блокируется. При ошибке отметка не меняется. После успешного сохранения клиент перечитывает счётчик; другие открытые страницы получают WebSocket-событие.

Соединения проверяются ping/pong и восстанавливаются с ограниченным числом повторов. Текущая серверная рассылка работает в одном процессе приложения.
