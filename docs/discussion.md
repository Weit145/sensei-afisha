# Обсуждения концертов — бэкенд MVP

Каждый концерт имеет одно обсуждение. Для запросов используйте UUID концерта
`afisha.id`; отдельный ID чата и поле `reviews_id` не нужны.

## Подключение

- Запуск — по [README](../README.md). В существующем окружении выполните `make migrate`.
- Концерт должен существовать в `afisha`, автор сообщения — в `users`.
- Авторизация использует `Authorization: Bearer <JWT>`. Токен должен содержать
  `user_id` (UUID пользователя), `role` (`user` или `admin`) и действительный `exp`.
  Для выпуска токена используйте существующую `src.infrastructure.jwt.create_token`;
  настройки JWT должны совпадать с настройками API.

Обсуждение не создает концерты и пользователей: это ответственность соответствующих
модулей. В текущей версии сервис афиши остается заглушкой, а маршруты входа не
подключены, поэтому для проверки нужны заранее сохраненные записи и тестовый JWT.

## API

Базовый адрес при стандартном запуске: `http://localhost:8080`.
Описание схем доступно в `/docs`.

| Запрос | Доступ | Ответ |
| --- | --- | --- |
| `GET /api/afisha/{afisha_id}/messages` | Всем, без токена | `200`, `{"items": [...]}` |
| `POST /api/afisha/{afisha_id}/messages` | Авторизованным, включая администратора | `201`, сохраненное сообщение |

GET возвращает всю историю от старых сообщений к новым, с сортировкой по
`created_at`, затем `id`. Если сообщений нет, ответ — `{"items": []}`.

POST принимает только `text`: строку длиной 1–2000 символов после удаления пробелов
по краям. Пустой текст и дополнительные поля запрещены. Автор берется из JWT;
`author_id`, ID сообщения и время создания передавать не нужно.

```http
POST /api/afisha/{afisha_id}/messages
Authorization: Bearer <JWT>
Content-Type: application/json

{"text": "Кто собирается на концерт?"}
```

Формат сообщения одинаков для ответа POST и элементов `items` в GET:

```json
{
  "id": "33333333-3333-4333-8333-333333333333",
  "afisha_id": "11111111-1111-4111-8111-111111111111",
  "author_id": "22222222-2222-4222-8222-222222222222",
  "text": "Кто собирается на концерт?",
  "created_at": "2026-10-14T15:00:00Z"
}
```

Время возвращается в UTC. Имя автора в ответ не входит.

| Ошибка | Причина |
| --- | --- |
| `401` | Нет действительного токена или его пользователь отсутствует в БД |
| `404` | Концерт отсутствует в БД |
| `422` | Некорректный UUID или тело запроса |

## Хранение и границы MVP

Сообщения хранятся в PostgreSQL, в таблице `discussion_messages`, с внешними ключами
на `afisha.id` и `users.id`. Физическое удаление концерта или автора, имеющего
сообщения, запрещено (`ON DELETE RESTRICT`). Отмена концерта сохраняет обсуждение.

Пагинация, удаление сообщений и WebSocket пока не реализованы. Поле `deleted_at`
подготовлено для мягкого удаления; помеченные записи возвращаются с текстом
«Сообщение удалено». Новые сообщения других пользователей доступны при повторном GET.
