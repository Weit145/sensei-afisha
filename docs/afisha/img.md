# Изображения афиш — бэкенд MVP

Изображение принадлежит одной [афише](afisha.md). Несколько изображений можно
загрузить при создании афиши; после создания файлы добавляются по одному.

## Подключение

- Запуск — по [README](../README.md): `make up` создаёт контейнеры и применяет миграции.
- Базовый адрес — `http://localhost:8080`, интерактивная схема — `/docs`.
- Изменяющие ручки изображений **сейчас не проверяют роль**: зависимость
  `require_admin` закомментирована. Сами файлы по `/uploads` публичны.

## API

| Запрос | Назначение | Ответ |
| --- | --- | --- |
| `POST /api/afisha/{afisha_id}/images` | Добавить один файл в поле `image` | `201`, `id` и `image_url` |
| `PATCH /api/afisha/{afisha_id}/images/{image_id}` | Сделать изображение обложкой | `200`, `null` |
| `DELETE /api/afisha/{afisha_id}/images/{image_id}` | Удалить изображение | `204`, без тела |

POST принимает `multipart/form-data` с одним файлом `image`. Поддерживаются
JPEG, PNG, GIF и WebP; формат определяется по содержимому файла, а не по его
имени. Афиша должна существовать.

```sh
curl -X POST http://localhost:8080/api/afisha/22222222-2222-4222-8222-222222222222/images \
  -F 'image=@./poster.jpg'
```

Ответ на добавление:

```json
{
  "id": "33333333-3333-4333-8333-333333333333",
  "image_url": "/uploads/4a5b6c7d8e9f00112233445566778899.jpg"
}
```

В `GET /api/afisha/{afisha_id}` каждое изображение дополнительно содержит
`is_cover` и `position`. Первое изображение становится обложкой. PATCH
назначает другую обложку, а при удалении текущей следующая выбирается по
`position`. В списке афиш ссылка на обложку находится в `cover_url`.

## Выдача файлов

`image_url` — относительный путь. Для показа изображения добавьте к нему
адрес API:

```text
/uploads/4a5b6c7d8e9f00112233445566778899.jpg
→ http://localhost:8080/uploads/4a5b6c7d8e9f00112233445566778899.jpg
```

Маршрут `/uploads` публичный и возвращает файл напрямую, без отдельной
API-ручки. Если файла нет, он отвечает `404`.

## Ошибки и хранение

| Код | Причина |
| --- | --- |
| `400` | Файл не является JPEG, PNG, GIF или WebP |
| `404` | Изображение не найдено при смене обложки или удалении |
| `422` | Некорректный UUID или отсутствует файл `image` |

Метаданные изображения хранятся в PostgreSQL. Файлы сохраняются в каталоге
`uploads` и Docker-томе `uploads_data`, поэтому переживают пересоздание
контейнера. Файлы не должны храниться в Git. При добавлении изображения к
несуществующей афише отдельная проверка пока не выполняется: ограничение БД
может привести к ответу `500`, а уже сохранённый файл будет удалён.
