# «Музыкальный понедельник» — фронтенд

React + JavaScript + Vite. Все изменения ограничены фронтендом; сервер, его схемы и миграции не менялись.

## Быстро посмотреть дизайн без бэкенда

Нужен Node.js 22.12+ (или 20.19+) и npm. Из корня проекта:

```sh
cd frontend
npm install
npm run dev:demo
```

Откройте **http://127.0.0.1:5173/**. Если порт занят, Vite напечатает другой адрес — используйте его.

В репозитории сохранён `package-lock.json` для воспроизводимой установки. Для чистой установки зависимостей используйте `npm ci`. Не смешивайте npm и pnpm в одной папке `node_modules`.

В режиме просмотра есть шесть демонстрационных концертов и пример обсуждения. Он явно обозначен полоской над меню. Регистрация и отправка сообщений отключены; сохранение личных планов работает в браузере. Примеры не загружаются в вашу базу. Ошибка реального API никогда не подменяется демонстрационными данными.

Что проверить:

1. На главной — поиск «Бах», переключение периодов и выбор месяца.
2. Откройте концерт: слева постер, описание и личный план; справа обсуждение; под описанием блок будущих отзывов.
3. Нажмите «Хочу пойти», перейдите в «Мои планы», обновите страницу — концерт сохранится.
4. Откройте «О клубе» и окно «Войти в клуб».
5. В инструментах разработчика браузера включите режим телефона и выберите ширину 390 px. На телефоне обсуждение располагается после описания и перед отзывами.

## Подключить существующий бэкенд

Запустите сервер по основному README проекта. По умолчанию API должно быть доступно на **http://127.0.0.1:8080**. Затем:

```sh
cd frontend
npm run dev
```

Откройте адрес Vite, обычно **http://127.0.0.1:5173/**. Прямой переход и обновление на `/concert/<UUID>` тоже поддерживаются сервером разработки.

Запросы `/api` и изображения `/uploads` проксируются на порт 8080, поэтому для локальной разработки не требуется менять CORS бэкенда. Если сервер использует другой порт, создайте `frontend/.env.local`:

```dotenv
API_PROXY_TARGET=http://127.0.0.1:8000
```

После изменения переменных перезапустите Vite. Для отдельно размещённого API можно задать `VITE_API_BASE_URL=https://api.example.com`; в таком случае сервер должен самостоятельно разрешать запросы с домена фронтенда.

Обычный запуск отображает только данные API. Если база пустая, будет пустая афиша. Концерты добавляются существующими средствами бэкенда (`/docs`). При недоступном API показывается ошибка с кнопкой повтора.

## Что уже связано с API

| Возможность | Существующий маршрут |
| --- | --- |
| Афиша, загрузка всех страниц | `GET /api/afisha?page=…&page_size=100` |
| Страница концерта и изображения | `GET /api/afisha/{id}` и `/uploads/…` |
| Название и адрес площадки | `GET /api/venues/{id}` |
| История обсуждения | `GET /api/afisha/{id}/messages` |
| Отправка сообщения | `POST /api/afisha/{id}/messages`, JSON `{ "text": "…" }`, Bearer JWT |
| Регистрация | `POST /api/auth/register`, JSON `{ "username": "…", "password": "…" }` |

Обсуждение обновляется периодически и по кнопке. Текст ограничен 2000 символами, отправка — кнопкой или Ctrl/⌘+Enter. Даты и время концертов показываются по Москве.

## Ограничения текущего API

- **Нет входа по паролю и выдачи JWT.** Регистрация создаёт пользователя, но не авторизует его. В окне «Войти» можно подключить уже выданный организаторами JWT с `user_id`, `role` и `exp`, совместимый с существующей авторизацией. Ключ хранится в `sessionStorage`; подпись проверяет бэкенд при отправке сообщения. Фронтенд не выпускает токены.
- **Нет API отзывов.** Блок отзывов оформлен, но публикация отключена с соответствующей подписью. Отзывы не записываются в поток обсуждения.
- **Нет API «хочу пойти» и списка участников.** Отметка реализована как личный план в `localStorage`, с явной подписью об этом. Она не синхронизируется между устройствами и не видна другим зрителям.
- **Нет профилей и имён авторов в ответе обсуждения.** Вместо выдуманных имён показывается сокращённый идентификатор «Слушатель XXXX»; полная идентификация остаётся за `author_id` в API.
- **Нет личных сообщений.** Кнопка «Найти компанию» ведёт в общее обсуждение концерта.

При добавлении этих возможностей на сервер фронтенд можно подключить к ним через `src/api.js`. Сейчас он не вызывает несуществующие маршруты.

## Сборка и проверки

```sh
npm test
npm run build
npm run preview
```

Готовая сборка находится в `frontend/dist`. Сервер публикации должен отдавать `index.html` для маршрутов `/concert/*`, `/plans` и `/club`, а `/api/*` и `/uploads/*` направлять на существующий бэкенд. `VITE_API_BASE_URL` применяется во время сборки.

13 автоматических проверок покрывают фильтры, даты на границе месяцев, хранение при недоступном браузерном хранилище, срок действия ключа, пагинацию API, Bearer-заголовок, формат регистрации, ошибки подключения и ограничения режима просмотра. Это проверки фронтенда с контролируемыми ответами API; работа с реальной базой требует отдельно запущенного бэкенда.

Оформление использует Georgia и Golos Text с системным запасным шрифтом. При отсутствии доступа к Google Fonts интерфейс сохраняет работоспособность. Векторные иллюстрации и обложки-заглушки находятся в самом приложении; загруженные постеры из API имеют приоритет.
