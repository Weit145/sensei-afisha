# Фронтенд клуба: реализация и проверка

Проверено 17 октября 2026 года. Изменения ограничены `frontend/`; бэкенд не менялся. Контракт сверен с `/openapi.json` запущенного приложения и текущими handlers, schemas, domain и usecase-кодом. WebSocket-протокол сверен с обработчиком `/api/ws`, поскольку FastAPI не включает его в OpenAPI.

## Реализовано

- Регистрация с немедленным входом, парольный вход, восстановление через refresh-cookie и проверка `/auth/me`, выход через API. Access token находится только в замыкании API-клиента. Пароль — только в состоянии открытой формы; старый ключ из sessionStorage удаляется при запуске.
- Все операции register/login/refresh/logout отправляют `credentials: include` и `X-Requested-With: XMLHttpRequest`. Они выполняются через одну очередь. Refresh объединяется для одновременно полученных 401, а Web Locks при наличии сериализует cookie-операции между вкладками. Неудавшийся защищённый запрос повторяется максимум один раз. Ошибка прав 403 не разлогинивает пользователя.
- Существующие афиша, поиск, фильтры, карточки, страница концерта и постеры. Рейтинг вычисляется из `rating_sum / reviews_count`. Серверное поле `followers_count` подписано «Интересуются». У постеров есть состояние загрузки и повтор при ошибке.
- «Мои планы» остаются локальным списком в браузере с явным пояснением приватности. Серверная статистика при нажатии не меняется. «Найти компанию» открывает обсуждение; личные сообщения и участники не имитируются.
- Обсуждение: GET/POST, cursor-пагинация через `before`, объединение по id, сохранение положения списка при добавлении ранних сообщений, получение всех пропущенных страниц после перерыва. WebSocket подписывается через `switch_afisha`; уведомление вызывает GET, его текст не добавляется в историю. Есть ping/pong, таймаут, пять попыток переподключения с задержками до 15 секунд и ручное обновление. При уходе запросы отменяются, сокет и таймеры закрываются.
- Отзывы: список и статистика, оценка 1–5 и текст, публикация после завершения опубликованного концерта, изменение и удаление своего отзыва. Свой отзыв показан первым, даже если он старше первой страницы API. После изменений список и статистика перечитываются. У будущего и отменённого концерта нет активной формы создания; существующий автор может менять/удалять отзыв, как позволяет сервер.
- `/admin` («Редакция») доступен только роли admin. CRUD площадок и афиш, создание афиши с JSON-строкой `afisha` и файлами `images` в multipart, обновление JSON, добавление одного `image`, назначение обложки и удаление изображения. Проверяются даты, площадка, статус, допустимые возрастные значения, координаты и сигнатуры JPEG/PNG/GIF/WebP. Удаление афиши требует подтверждения с описанием связанных удаляемых данных.
- Сохранены кремовый фон, винный цвет, Golos Text, засечки, редакционная композиция и существующие постеры. Новые формы адаптированы к мобильным экранам. Добавлены подписи полей, уведомления/ошибки с live-region, видимый фокус, изоляция фона модального окна, Tab/Shift+Tab, Escape и возврат фокуса.

## Автоматические проверки

В папке `frontend/`:

```sh
npm ci
npm test
npm run build
```

Все 23 теста проходят. Проверяются cookie/CSRF, `/me`, восстановление без сохранённого токена, одновременные и запоздавшие 401, максимум один повтор, гонка logout/refresh, 403 без потери сессии, разные сообщения для 401/403/409/422/ошибки сети, 204 и JSON null, multipart и JSON, отмена запроса во время общего refresh, пагинация, протокол WebSocket, ping/pong, ограниченный backoff, очистка соединения, объединение сообщений, рейтинг, допустимость отзывов и админская валидация.

## Обнаруженное ограничение текущего API

При создании тестовой афиши сервер один раз вернул `400 invalid_data` с сообщением «Дата обновление не может быть раньше или равна созданию». В domain-модели есть сравнение `updated_at <= created_at`, при этом оба значения создаются подряд через часы с микросекундной точностью и иногда совпадают. Повторный самостоятельный запрос с теми же данными прошёл. Фронтенд показывает серверную ошибку и не повторяет автоматически такие записи; исправление требует отдельной правки бэкенда.

## Чего пока нет на бэкенде

Для настоящего серверного «хочу пойти» требуются операции подписки и отписки авторизованного пользователя от афиши, чтение его текущего статуса подписки и списка его подписок, а также согласованное обновление `followers_count`. Для будущего публичного поиска компании дополнительно нужны список заинтересованных с правилами приватности и согласие пользователей на показ. Этих ручек в текущем контракте нет; фронтенд их не вызывает. Подписка сама по себе не означает подтверждённое посещение. Личные сообщения и обмен контактами не реализуются и не имитируются.

## Локальный запуск

```sh
cd frontend
npm run dev
```

По умолчанию Vite проксирует `/api` (включая WebSocket) и `/uploads` в `http://127.0.0.1:8080`. Другой адрес задаётся `API_PROXY_TARGET`. `VITE_API_BASE_URL` нужен только для отдельного origin API; тогда сервер должен разрешать origin сайта и credential-запросы через CORS. Для локального HTTP серверу требуется `AUTH_COOKIE_SECURE=false`, для HTTPS — secure-cookie. Деморежим остаётся явно обозначенным режимом чтения с `npm run dev:demo`.
