# Контакты и расположение площадки

Контракт сверен 17 октября 2026 года с OpenAPI текущего запущенного приложения, `docs/users.md`, обработчиками контактов и схемами Venue. Бэкенд не менялся.

## Что добавлено

- Раздел `/contacts`, доступный через «Мои контакты» после входа. Получение: `GET /api/auth/me/contacts`; сохранение: `PATCH /api/auth/me/contacts` с Bearer, JSON и `X-Requested-With: XMLHttpRequest`. Пустое поле отправляется как `null`; оба поля отправляются явно. API-метод поддерживает и частичное обновление: пропущенные поля не добавляются в запрос.
- Проверка HTTPS, длины до 255 символов и точных доменов t.me / telegram.me / vk.com. Ошибки показаны у полей; есть состояние сохранения, подтверждение успеха и пояснение доступности контактов другим вошедшим участникам. Пока первоначальное чтение не удалось, сохранение не предлагается, чтобы не затереть существующие ссылки пустыми значениями.
- Кнопки авторов в сообщениях и отзывах открывают `GET /api/users/{author_id}/contacts`. Настоящий ник берётся из ответа карточки. Ник из WebSocket связан с `user_id` и используется для подписи новых сообщений; текст уведомления по-прежнему не заменяет GET истории. Для отсутствующих контактов ссылок нет; для гостя предлагается вход; для 404 — понятная ошибка и повтор. Ссылки имеют `target="_blank" rel="noopener noreferrer"`. Личные сообщения не имитируются.
- Все контактные запросы проходят через существующий API-клиент, используют его последовательный refresh и максимум один повтор. Контакты не сохраняются в localStorage/sessionStorage, запросы идут с `cache: no-store`, карточка закрывает доступ к данным после выхода или смены пользователя.
- Карта Leaflet в общей форме создания/редактирования площадки: поиск по адресу, выбор найденного результата, установка точки кликом, перетаскивание и клавиатурный выбор, связь с latitude/longitude, удаление маркера. Изменения отправляются только при сохранении площадки её существующим API. Адрес, город и название остаются ручными полями; поиск не переписывает их автоматически.
- На странице концерта карта показывается только при наличии обеих корректных сохранённых координат. Начальный обзор карты не записывается как положение и не создаёт маркер. Площадка для концерта по-прежнему выбирается по ID из существующих площадок.
- Отказ поиска, загрузки тайлов или самой библиотеки не блокирует ручное сохранение площадки. Есть повтор загрузки карты. Карта очищает обработчики и экземпляр Leaflet при закрытии, поиск отменяет устаревшие запросы. Результаты поиска кешируются в памяти, новые запросы ограничены интервалом 1,2 секунды; поиска при наборе текста нет.

## Переменные окружения

Обязательных новых переменных и API-ключей нет. Значения по умолчанию:

| Переменная | Назначение |
| --- | --- |
| `VITE_MAP_TILE_URL` | `https://tile.openstreetmap.org/{z}/{x}/{y}.png`; шаблон URL растровых тайлов. Значение `off` отключает карту. |
| `VITE_MAP_ATTRIBUTION` | `© OpenStreetMap contributors`; видимый текст атрибуции, ссылка на лицензию OSM остаётся на карте. Для другого провайдера настройте корректную атрибуцию. |
| `VITE_GEOCODER_URL` | `https://photon.komoot.io/api/`; URL сервиса с контрактом Photon GeoJSON (`q`, `limit`, `features`, координаты `[longitude, latitude]`). Значение `off` отключает поиск. |

После изменения переменных Vite нужен перезапуск dev-сервера или новая сборка. Существующие `API_PROXY_TARGET` и `VITE_API_BASE_URL` не меняются. Все `VITE_*` публичны и попадают в клиентскую сборку: секретные ключи здесь размещать нельзя. Для сервиса с секретным ключом потребуется отдельный серверный прокси, которого текущий backend не предоставляет; такой эндпоинт фронтенд не придумывает.

Карта использует стандартное браузерное кеширование и только видимые тайлы, с видимой атрибуцией и Referer. У публичных сервисов нет гарантии доступности. Для роста нагрузки замените Photon на собственный/договорной совместимый сервис и настройте провайдера тайлов. Требования: [политика тайлов OpenStreetMap](https://operations.osmfoundation.org/policies/tiles/), [Photon и условия публичного сервера](https://github.com/komoot/photon#demo-server), [API Photon](https://github.com/komoot/photon/blob/master/docs/api-v1.md), [Leaflet](https://leafletjs.com/reference.html). Публичный Nominatim не подключается.

## Проверки

`npm test`: 35 тестов проходят. `npm run build`: проходит. Новые проверки покрывают допустимые и опасные URL, null и пропущенные поля, заголовки PATCH, nickname, 404 и повтор, 401 с успешным и истёкшим refresh, отсутствие сетевых запросов гостя, отмену, данные WebSocket, реальные/отсутствующие координаты, протокол Photon, отсутствие утечки Bearer/cookie во внешний поиск, кеш, ограничение частоты и отказ сервиса.

Ручная проверка выполнена на настоящем API, в отдельной локальной тестовой базе:

- Добавление, изменение и удаление своих контактов с повторным открытием страницы; ошибка неверного протокола рядом с полем.
- Чтение контактов другого пользователя, настоящий ник, только существующие кнопки, правильные атрибуты внешних ссылок.
- Пользователь без контактов; переход из карточки в обсуждение; приглашение гостю войти.
- 404 удалённого автора и повторный запрос. Для подготовки удалены только тестовые сообщение и автор в тестовой базе; устаревшее сообщение оставалось в уже открытой истории. Пользовательское удаление аккаунтов не добавлялось.
- Поиск реального публичного адреса, выбор результата, клик, перетаскивание, выбор точки с клавиатуры; сохранение через API и совпадение координат после повторного открытия площадки.
- Недоступные тайлы и поиск проверены в отдельном просмотре с адресом локального неработающего сервиса: ошибки отображаются, площадка успешно сохраняется.
- Создание площадки без координат: маркера нет, сохранение работает. Затем в форме афиши выбрана эта уже созданная площадка по её ID; на странице концерта показан адрес, карты и фиктивного маркера нет.
- Живое сообщение другого участника пришло через WebSocket, история перечитана GET без дубликата, имя автора показано из `nickname`; по кнопке открылась его настоящая контактная карточка.
- При ширине 390 px проверены «Мои контакты», карточка участника, публичная карта и редактор площадки: горизонтального переполнения нет. Дополнительная строка навигации занимает собственное место и не перекрывает страницу.
- Проверены стрелки/Enter для выбора точки, Tab/Shift+Tab внутри контактной карточки, Escape и возврат фокуса на кнопку автора. Ссылки и числовые поля доступны с клавиатуры.

Истечение сессии проверено автоматическими управляемыми ответами 401, а не ожиданием 30 минут в браузере.

Для запрошенных контактов и сохранения координат контракт backend достаточен. Геокодирования в нём нет — используется явно отдельный внешний Photon. Новых backend-ручек для этих сценариев не требуется.
